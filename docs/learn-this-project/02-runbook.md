## First-time setup

Run in order from the project root (`/Users/sanhehu/Documents/GitHub/prompt_risk-project/`):

```bash
# 1. Install mise-managed tools (Python 3.12, uv, claude, pandoc)
mise install

# 2. Create the .venv and install all dependencies (uv sync --all-extras)
mise run inst

# 3. (One-time) Configure your AWS profile
aws configure --profile yuan_yingqiang_dev
# Region: us-east-1 (or wherever Bedrock + Nova Lite is available to you)
# Ensure the IAM identity has bedrock:InvokeModel + bedrock:Converse on us.amazon.nova-2-lite-v1:0
```

If you don't have that AWS profile, edit `prompt_risk/one/one_03_boto_ses.py:16` to your own profile name (or wire up environment-based credentials). Unit tests do not call Bedrock; they will pass without AWS.

Verify setup:

```bash
mise run cov   # should run pytest, show coverage report
```

## Day-to-day commands

| Task | Command | What it does |
|--|--|--|
| Install / sync deps | `mise run inst` | `uv sync --all-extras`. Idempotent. |
| Run all unit tests | `mise run test` | `.venv/bin/pytest tests`. No LLM calls. |

| Open coverage report | `mise run view-cov` | Opens `htmlcov/index.html`. |

| Build docs | `mise run build-doc` | Sphinx → `docs/build/html/`. |
| Open built docs | `mise run view-doc` | Opens `docs/build/html/index.html`. |
| Convert `.ipynb` demos to `.md` | `mise run notebook-to-markdown` | For AI knowledge base (so AI assistants can read notebook content). |
| Launch Jupyter Lab | `mise run lab` | For interactive demo notebooks. |
| Build wheel + sdist | `mise run build` | Outputs to `dist/`. |
| Publish to PyPI | `mise run publish` | Requires `$PYPI_TOKEN`. |

## Running locally

This is a **library**, not a service — there's no dev server. You exercise it by running example scripts that hit real Bedrock:

```bash
# UC1 pipeline — step by step (each script pins a prompt version + test case)
python examples/uc1-claim-intake/run_uc1_p1_extraction.py
python examples/uc1-claim-intake/run_uc1_p2_classification.py
python examples/uc1-claim-intake/run_uc1_p3_triage.py

# P1 business-correctness judge (different from J1 security judge)
python examples/uc1-claim-intake/run_uc1_p1_extraction_judge.py

# J1 security judge on a UC1-P1 prompt version
python examples/judges/run_j1_on_uc1_p1.py
```

To **change which test case or prompt version** runs: edit the file. There's a block of commented-out `case = P1LoaderEnum.…` lines near the top — uncomment one and comment the others (see `examples/uc1-claim-intake/run_uc1_p1_extraction.py:10-18`). To switch prompt versions in `run_j1_on_uc1_p1.py`, uncomment the desired `PROMPT_VERSION` line (`:19-22`).

Each script prints to stdout — there's no log file, no HTTP endpoint, no browser URL.

## Tests

Unit tests live in `tests/`. They are **in-memory only** — no LLM calls, no AWS, no network.

```
tests/
  test_api.py          # import sanity check
  test_evaluations.py  # evaluate() with eq / in / ne; AND semantics
  test_llm_output.py   # extract_json() on fenced / bare / multi-text JSON
  test_prompts.py      # Prompt path resolution via PromptIdEnum
  all.py               # pytest discovery root
```

Run modes:

```bash
mise run cov                         # all tests + coverage
python tests/test_evaluations.py     # one file as subprocess, scoped coverage
.venv/bin/pytest tests/test_prompts.py -v   # one file via pytest directly
```

What's **not** tested (by design — `.coveragerc` omits these):

- `prompt_risk/uc/uc1/*_runner.py` — LLM-dependent, would need mocked Bedrock.
- `prompt_risk/one/one_03_boto_ses.py` — Creates AWS session.
- `prompt_risk/vendor/` — vendored utilities.

The covered modules are pure logic: `evaluations.py`, `prompts.py`, `llm_output.py`, `constants.py`, `paths.py`, `exc.py`.

To exercise LLM-dependent code paths, use the `examples/` scripts manually — they're not in CI to save cost.

## Common failures and fixes

| Symptom | Cause | Fix |
|--|--|--|
| `ProfileNotFound: The config profile (yuan_yingqiang_dev) could not be found` when running an example | You don't have the author's hardcoded AWS profile | Edit `prompt_risk/one/one_03_boto_ses.py:16` to your profile name, or `aws configure --profile yuan_yingqiang_dev` |
| `AccessDeniedException` from Bedrock | IAM identity lacks `bedrock:InvokeModel` / `Converse` for the model | Add the policy, or pass `model_id="..."` for a model your account has access to |
| `JsonExtractionError` after 3 attempts | LLM consistently returned unparseable / invalid JSON | Check the prompt; LLM may have been hijacked by an attack payload. The `JsonExtractionError.raw_output` carries the full text. |
| `ValidationError` propagated from a runner | All 3 retries failed; output schema mismatch persisted | Same as above. Check the `raw_output`. May be a model-too-small problem — try `model_id="us.anthropic.claude-…"`. |
| Unit tests "pass but I can't import the package" | `.venv` not active when running outside `mise` | `source .venv/bin/activate` or use `.venv/bin/python` directly |
| `htmlcov/index.html` doesn't open | Wrong tool; macOS `open`, Linux `xdg-open` | `mise run view-cov` uses `open`; rewrite to `xdg-open` on Linux |
| `mise.toml` complains about `home-secret-toml` | The secret-loader isn't installed | `uvx --from home-secret-toml hst get ...` should auto-install on first run. If you don't need those env vars (`$GITHUB_TOKEN`, etc.) for what you're doing, ignore — the related tasks (`publish`, `release`, `setup-codecov`) won't run. |
| Demo notebook in `docs/source/06-…/index.ipynb` won't render in Sphinx | `nbsphinx` requires kernel info | Re-export with `mise run notebook-to-markdown` (uses pandoc 3.9), or open in Jupyter Lab and re-save |

## Where to look when something breaks

| Need | Look here |
|--|--|
| What did the LLM actually return? | `JsonExtractionError.raw_output` (if raised) or add a `print(text)` in the runner right after `text = converse(...)` |
| Why did my Pydantic validation fail? | The retry feeds the error back as a user message — read the conversation history (`messages` list at the moment of failure) |
| Where is the prompt file the runner is reading? | `Prompt(id=..., version=...).path` — e.g. `prompt = Prompt(id=PromptIdEnum.UC1_P1_EXTRACTION.value, version="01"); print(prompt.path)` |
| Did the test case actually load? | `loader = P1LoaderEnum.b_06_ambiguous_lob.value; print(loader._toml, loader.data, loader.expected, loader.attack_target)` |
| Which model is the runner calling? | The `model_id` parameter on the runner function. Default for P1 is `us.amazon.nova-2-lite-v1:0` (`prompt_risk/uc/uc1/p1_extraction_runner.py:86`). |
| Coverage stats by file | `htmlcov/index.html` after `mise run cov` |
| Github CI logs | `gh run list --limit 10`; or browser at `https://github.com/YingqiangYuan/prompt_risk-project/actions` |
| ReadTheDocs build status | `https://yq-prompt-risk.readthedocs.io/en/latest/` (badge in `README.rst`) |

No production monitoring dashboards — this is a development-time library. Once Gate 3 (continuous monitoring) is implemented per the governance doc, this section will grow.
